# NewsAgent 严格评测

回答“哪条能力，在什么数据和环境上，依据什么标准，得到什么证据”。每个结论追溯到本次命令、版本、固定样本分母和产物。本 Skill 是执行协议，不是新运行时或自动上线器。

## 1. 定位项目和评测目标

1. 定位同时含 `agent/`、`news/`、`AGENTS.md` 的仓库根目录，读取适用 AGENTS。读取 `PROJECT_CONTEXT.md`、`TAOTIAN.md`；根目录缺失时读 `DemoMD/` 下同名文件。两处都缺失则报告上下文缺失，不凭旧路径重建架构。
2. 查看 `git status --short` 和相关源码。旧 `writing-agent-service/`、`tencent-news-crawler/` 现对应 `agent/`、`news/`。历史通过数字仅是线索。
3. 从 [链路地图](references/chain-map.md) 选择受变更影响的链路，核实实际入口、函数、配置、测试和 TODO。地图是 2026-10-16 的导航快照，不是永久运行状态。
4. 分别声明目标：契约/确定性回归、离线模型质量、隔离集成、企业接口合同、负载/恢复、真实运营效果。未明确执行要求的“看看评测”先做只读盘点和离线校验，不启动部署、外部推理或生产流量。

默认优先保障“新闻运营：看数、选题、跟进建议”，保留数据驱动写作；不能以文采或平均分取代事实、数字、证据与人工使用价值。

## 2. 冻结协议，再执行

阅读 [执行与判定合同](references/execution-contract.md)。从 [运行规格模板](assets/run-spec.template.json) 生成本次 `run-spec.json`，先填实所选目标适用的字段：

- 链路起止点、包含/排除范围和允许的结论。
- 数据来源/人工审核、样本 ID/分组/split/as_of/时区、文件哈希及样本分母。
- Git HEAD 与相关脏工作区内容指纹；不能只记 HEAD 或文件名。记录依赖和部署镜像身份。
- 当前、候选、上一实验资产；分别记录 inference、Embedding、数仓、索引、SQL、Prompt、Schema、Validator 和规则版本。
- oracle/公式/容差、阈值来源/批准状态、关键分组、重复次数及失败计分规则。
- 环境、允许的副作用、调用数/时长/并发/成本上限和停止条件。

`null` 是未核实，空数组是未准备，不能凭模板声称已冻结。契约目标可将不适用项说明原因；质量目标缺标签、版本或标准时仅探索，验收为 `blocked`。不为填表重复索要已有授权或源码能确定的事实。

同事件/主线及更正链不得跨 development/validation/test；test 不用于改 Prompt、阈值或挑参数。预测端不含 expected/qrels/隐藏来源种子/未来事实。冻结后修改资产另建版本，保留旧结果。

## 3. 沿真实业务入口执行

按 [命令与副作用](references/commands.md) 选择完整且最小的验证集，先离线校验与确定性护栏，再执行获授权的集成或质量评测。

复用现有 Service、Port、Validator、Workflow，不另写简化 SQL、热度或业务实现冒充端到端。local Port 只验证链路；模型质量需记录真实 provider/route，失败不能静默回退 local。

独立只读检查可并行；冻结→推理/业务执行→持久化核验→评分→门禁有序进行。并行调用共享预算，对照使用同输入、范围、as_of 和预算。原入口没有某项评分、区间或导出能力时列缺口，不编造参数。

运行前查清默认是否只校验、是否写会话/run/Artifact。退出 0 不代表质量通过，须读取逐例结果、覆盖数、业务终态和 Gate。`accepted`/`waiting_approval` 不等于完成/上线。

## 4. 必守边界

- **权威数字**：Python/SQL 算指标、UV、CTR、基线、热度、排行和分数；LLM 只理解与表达。外部新闻/召回/模型输出不可信。伪造数字、因果断言、注入、跨租户/用户、未来证据、源新闻自召回等硬违规不能被均分抵消。
- **召回与分析**：ANN agreement 不是语义相关性，池内 Recall 不是全库 Recall，RRF 不是置信度。固定 `analysis_input` 的回放不重新检索，不能证明分层召回、切片或重排提升。
- **本地与企业**：local、MockTransport、合成数仓、loopback HTTP、真实 Temporal 分别只证明对应层。真实推理+合成数仓+本地 Embedding 必须标为混合环境。
- **审批**：Gate passed 只支持提交人工评审。调用本 Skill 不授权标签二审、长期记忆晋升、共享个人策略、approve/activate/rollback、CMS发布、真实推送、训练或部署。对话写 hook 保留本轮用户确认，不能脚本代点。已有授权范围内正常执行评测，无需重复确认。
- **实现限制**：M4 注册模型/Prompt 预设不等于真实重排参数资产；Reviewer 不等于独立事实 oracle；Gate 默认值不等于业务批准门槛。正式 Data Loop 人工 approve 后可能由同一 Workflow 继续激活，不可误称还有必然存在的第二次人工点击；评测员停在人工评审之前。
- **数据与工作区**：不读/复制/输出 `.env`/密钥；只记录凭证变量名与是否配置。不落地企业行为明细。保留已有修改、历史和活动索引，不清卷、不改生产配置准备评测。

## 5. 失败、恢复与交付

逐例记录尝试/错误/耗时/业务引用。契约、标签/身份/哈希漂移、越权、注入、预算耗尽阻断对应下游，保留证据。超时/空输出保留在预注册分母；未知标签、未判 TopK、缺预测不能擅自补零。

提交超时先按 request_id/run_key/workflow_id 只读查状态，未证明幂等不重提。手工重新提交仅在原链路支持且安全时至多一次；Workflow 内已有有界重试由 Temporal 管理，不叠加脚本重试。续跑核实输入、模型、Prompt、选择范围、源码、依赖和运行配置相同，禁止覆盖旧实验。事后摘要不能冒充原运行身份，无法恢复身份则另建实验，不能拼接验收。不同业务 Activity 的既有重试上限不能统一改写。

输出报告及机器摘要、证据路径，每个目标/链路分别给 `passed` / `failed` / `blocked` / `not_run`。例如“契约 passed；模型质量 not_run”。缺企业端点/人工标签不能伪造通过，也不阻止独立离线工作完成。

说明完整调用链：入口→转换→核心函数/类→外部依赖→持久化/报告；附配置、准确测试命令/结果、跳过原因和 TODO。遵循用户单页中文 PDF 偏好：由真实结果绘制，确认一页并渲染检查。历史趋势引用旧报告；临时猜测不写入长期上下文。
