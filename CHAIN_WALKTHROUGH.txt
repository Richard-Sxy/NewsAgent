NewsAgent 全链路阅读与关键修复指南
===================================

建议按照一次任务的真实运行顺序阅读，而不是按照文件夹顺序阅读。


一、API 创建任务与重复启动保护
------------------------------

文件：
writing-agent-service/app/api/jobs.py

重点代码：

job, created = await jobs.create_or_get(...)
await session.commit()

if created or job.status.value == "created":
    await orchestrator.start_job(job)

这里解决两个问题：

1. PostgreSQL 任务先落库，再启动 Temporal。
2. 已经进入运行状态的任务，不会因为相同 idempotency_key 再启动 Workflow。

继续阅读：
writing-agent-service/app/services/job.py

重点代码：

.on_conflict_do_nothing(
    index_elements=[
        WritingJob.tenant_id,
        WritingJob.idempotency_key,
    ]
)

执行关系：

HTTP 重试
  -> tenant_id + idempotency_key
  -> 返回原 WritingJob
  -> 不会创建第二条 Agent 链路


二、Temporal 启动与人工决策
--------------------------

文件：
writing-agent-service/app/services/orchestrator.py

启动任务的关键配置：

id_conflict_policy=WorkflowIDConflictPolicy.USE_EXISTING
id_reuse_policy=WorkflowIDReusePolicy.REJECT_DUPLICATE

它与数据库幂等键形成双重保护：

PostgreSQL：防止重复 Job
Temporal：防止重复 Workflow

人工决策发送前先查询 Workflow Snapshot：

snapshot = await handle.query(
    NewsWritingWorkflow.snapshot
)

然后检查当前等待的 gate：

if snapshot.waiting_gate != decision.gate:
    raise InvalidHumanDecisionError(...)

例如 Workflow 等待 outline，却提交 research，API 返回 409。


三、Temporal 主链路
------------------

文件：
writing-agent-service/app/workflows/news_writing.py

执行顺序：

run()
  -> research
  -> 人工确认
  -> outline
  -> 人工确认
  -> section_draft 循环
  -> assemble
  -> review 循环
  -> section_revise
  -> finalize

审核最多三轮：

while self._review_round < 3:
    self._review_round += 1

超过三轮转入 WAITING_HUMAN，防止 Writer 和 Reviewer 无限返工。


四、人工取消和转人工时同步数据库
--------------------------------

相关文件：

writing-agent-service/app/workflows/news_writing.py
writing-agent-service/app/services/job_state.py

Workflow 不再只返回结果，而是先执行：

await self._transition_state(
    request,
    "waiting_human",
    reason,
)

或者：

await self._transition_state(
    request,
    "cancelled",
)

调用关系：

Workflow 控制状态改变
  -> transition_job_state Activity
  -> JobStateHandler
  -> PostgreSQL WritingJob 同步

JobStateHandler 最终执行：

job.status = target
job.current_step = None


五、Activity 心跳
----------------

文件：
writing-agent-service/app/activities/news_steps.py

Workflow 配置 heartbeat_timeout=30 秒，因此 Activity 必须发送心跳。

当前每十秒执行：

activity.heartbeat("agent step is running")
await asyncio.sleep(10)

如果没有心跳，一个运行两分钟的 FastGPT 请求可能在第 30 秒被 Temporal
当成失联 Activity。


六、Agent 分派和 Checkpoint 主链路
--------------------------------

文件：
writing-agent-service/app/services/news_step_handler.py

执行关系：

准备 WritingStep/AgentRun
  -> 加载输入 Artifact
  -> 调用具体 Agent
  -> 校验 Agent 输出
  -> 写入 S3
  -> 提交 PostgreSQL Checkpoint

分派入口：

result = await self._dispatch(command, policy)

跨上下文校验：

self._validate_agent_result(command, result)

成功提交：

artifact_pipeline.persist_success(...)


七、防止 Agent 输出串任务
------------------------

文件：
writing-agent-service/app/services/news_step_handler.py

校验 job_id：

if value.job_id != command.job_id:
    raise AgentOutputValidationError(...)

章节校验：

value.section_id == command.inputs["section_id"]

审核轮次校验：

value.review_round == command.inputs["review_round"]

还会检查 Reviewer 返回的 section_id 是否真实存在。

它防止格式正确、但属于其他任务或章节的数据进入 Checkpoint。


八、研究和提纲返工上下文
------------------------

研究 Agent：
writing-agent-service/app/services/agents/research.py

现在会收到：

previous_research_package
revision_instruction

提纲 Agent：
writing-agent-service/app/services/agents/writer.py

现在会收到：

previous_outline
revision_instruction

因此返工不再只是重新调用一次 Agent，而是携带上一版本和修改要求。


九、章节定点返工
----------------

Schema：
writing-agent-service/app/schemas/writing.py

新增：

current_section: ArticleSection | None

并校验 current_section 的 job_id 和 section_id。

Handler 会从 Artifact Store 加载原章节：

current_section = await self._load(
    inputs["current_artifact"],
    ArticleSection,
)

章节返工输入现在包含：

原章节
+ 审核问题
+ 提纲
+ 研究包


十、审核轮次写入数据库
----------------------

相关文件：

writing-agent-service/app/schemas/checkpoint.py
writing-agent-service/app/services/news_step_handler.py
writing-agent-service/app/services/checkpoint.py

Checkpoint 命令包含：

review_round: int | None

最终写入 Job：

job.review_rounds = max(
    job.review_rounds,
    command.review_round,
)

因此 API 查询到的 review_rounds 与 Temporal 实际轮次保持一致。


十一、幂等重放保护
------------------

文件：
writing-agent-service/app/services/news_step_handler.py

关键状态：

prepared.replay_artifact
checkpoint_committed

如果步骤已经成功：

if prepared.replay_artifact is not None:
    return await self._replay_outcome(...)

只有当前步骤没有成功、且 checkpoint 尚未提交时，才允许记录失败。

它防止已经成功的 AgentRun 在 Temporal 重放时被错误修改为失败。


十二、推荐阅读顺序
------------------

1. app/api/jobs.py
2. app/services/orchestrator.py
3. app/workflows/news_writing.py
4. app/activities/news_steps.py
5. app/services/execution.py
6. app/services/news_step_handler.py
7. app/services/artifact_pipeline.py
8. app/services/checkpoint.py
9. app/services/recovery.py

优先理解三个文件：

Workflow：决定下一步执行什么。
StepHandler：决定这一步具体怎么执行。
CheckpointService：决定什么时候算真正完成。
