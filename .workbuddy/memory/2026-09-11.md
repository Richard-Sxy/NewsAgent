2. `HotNewsAnalysisInputBuilder.build()`：只传权威指标 + 热度四分量 + 正文/摘要各截 2000 字 +

### Data Loop 主线五步（已核源码）
`HotNewsDataLoopWorkflow.run()` 固定顺序：`freeze_dataset` → `attribute_errors`（失败只标记
`degraded`，不阻塞）→ `evaluate_candidate`（返回 `gate_passed`，false 即
`evaluation_failed` 终止）→ 等人工决定（`workflow.wait_condition` 超时 48h，超时记
`system/reject` → `approval_expired`）→ `record_promotion_decision` → 若 approve 再
`activate_bundle`。全部经单一 Activity `run_data_loop_step`，由
`HotNewsDataLoopStepHandler.execute()` 的 handlers 字典分发
（`freeze_dataset` / `attribute_errors` / `evaluate_candidate` / `record_promotion_decision` /
`activate_bundle`）。
决策是 **Temporal Update**（`submit_promotion_decision`，带 `@validator`），非 Signal：
原子接受一条决定并返回幂等回执；重复键同内容返回 `created=false`，同键不同内容报错。
幂等：Workflow ID = `sha256(tenant_id \x1f idempotency_key)`；请求指纹存 memo，冲突抛
`DataLoopStartConflictError`；Update ID、激活、恢复各有独立 sha256 键。
`HotNewsDataLoopActivationRecoveryWorkflow` 只重放「已批准但激活未完成」：
先重放原审批账本，再用与原审批完全相同的 `:activate` 幂等键重放激活。已激活或已回滚后调用
`recover` 必须被拒。

### 两条链路的桥接点
`HotNewsDecisionService.record_decision` 是热点控制台进入 Data Loop 的入口：在**同一数据库

生成 Feedback Case。发布侧由 `PublicationOutcomeFeedbackService.record_and_collect` 按策略回流。
