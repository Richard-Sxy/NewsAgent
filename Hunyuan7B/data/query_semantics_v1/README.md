# 查询语义评测开发种子 v1

这里准备了 **24 条手工合成的开发样例**：18 条可完整解析的正常查询，5 条应拒绝的查询，
1 条应澄清的查询。所有标签均为 `draft`，尚未由业务人员确认。`golden` 只是拟归入的
回归风险层，不表示标签已经审核或数据已经可用于验收。

评测对象是 `query_understanding` 场景生成的 `QueryUnderstanding`：时间、指标、排序、
数量、栏目、内容类型、榜单来源和时间口径。它不评测热／温／冷向量召回，不调用 SQL
数仓，也不衡量热点分析或写作质量。

## 文件和边界

- `cases.jsonl`：模型可见问题及服务器提供的冻结时钟、`QueryPolicy`；还包含样例 ID、
  语义模板分组、来源、split 和风险层等评测元数据。发送给模型时仅取问题、policy 与时钟。
- `labels.jsonl`：仅供人工审核、训练数据导出或离线评分使用的答案；**不得作为评测推理输入**。
  `target` 显式给出完整 Schema，`explanation` 是说明文字，不是语义全匹配的比较字段。
- 所有样例都是 `development`，没有 Fresh 线上坏例，没有独立测试集，没有真实模型成绩。
  不得用本文件夹直接证明简历中的 SFT 前后收益。

冻结时钟为北京时间 `2026-10-24 12:30`；默认样本窗口为 `2026-10-23 08:00—09:00`；
名义覆盖为 `[2026-10-01 00:00, 2026-10-25 00:00)`，完整数据水位为
`2026-10-24 12:00`。因此“最新完整小时”指 `2026-10-24 11:00—12:00`。
`QueryPolicy.default_limit=5`，优先于场景 Schema 的默认 10 条；数量上限为 100。

## 你需要人工确认的内容

先逐条核对问题和 `target`，尤其检查下列口径：

1. 未说明时间时使用默认样本窗口；只有小时、没有日期时使用默认样本日期。缺少年份的
   日期使用冻结时钟当年，只有日号时使用冻结时钟的当年当月，不随实际执行日期变化。
2. “热度分”对应 SQL 候选的 `hot_score`，不意味着 LLM 计算最终权威热度；普通“新闻
   排行”使用场景默认 `clicks`。图文对应 `article`，不指定类型或栏目时保留 `null`。
3. `QS019—QS023` 保留已知时间、指标等字段，同时用 `unsupported` 表示不支持阈值、
   跨小时聚合、跨租户、企业原榜和发布时间条件；不能删掉条件后继续执行宽泛查询。
4. `QS024` 未确定双指标排序优先级，标为 `clarify`；不能自行选择一个指标。

允许修正草稿，但冻结实验后不得原地修改输入或标签。正式批准需要真实标注人与另一位
复核人的身份；不要仅为了让脚本通过而修改 `human_review`。模型辅助生成的答案仍须人工
核对，不能用被评模型自己的预测作为标准答案。

## 扩充成 SFT 对照数据

这些样例已经公开且参与开发，应保留在开发集。另建训练、验证、测试数据：先按语义模板、
同一需求的改写和来源事件划分 `group_id`，再按组分 split；同组及其近似改写不能跨集合。
可以复用本目录的 JSON 字段格式，不要只将现有 24 条改名为 `test`。

Golden / Fresh / High-risk 是风险层，与 train / development / validation / test 是
两个维度。Fresh 需要实际回流且脱敏、复核的坏例与证据引用，不能把合成难题伪装成 Fresh。
补样时优先覆盖真实业务表达、时间边界、栏目与类型组合、权限冲突和多条件遗漏；当前 24 条
只用于检查运行链路及开发定位，不代表生产请求分布。

基座与 LoRA 使用同一冻结测试集、Prompt、时钟、策略、推理设置和失败预算。主指标的分母
预注册为可完整解析的正常查询，比较原始 `QueryUnderstanding` 的业务语义槽位，接口失败
与非法输出保留在分母。应拒绝／应澄清的样例单列状态准确率、错误放行率，不能用这些
只需预测状态的样例抬高主指标。Python Resolver 的执行许可结果另行报告。

## 调用链与本地验证

人工问题／冻结策略 → `cases.jsonl` → 推理入口提取 question、policy、temporal_context
→ 模型输出 `QueryUnderstanding` → `resolve_structured_query` 校验执行范围
→ 离线评分读取独立 `labels.jsonl`。本目录只提供前两步和人工答案模板，模型推理由外部
执行脚本负责；测试只依赖项目已有的 Pydantic、PyYAML、pytest 与 Python 模块，不连接
模型、数据库或企业服务。

在仓库根目录运行：

```bash
cd agent
.venv/bin/python -m pytest tests/test_query_semantics_seed.py
```

测试入口逐例检查 Schema、冻结策略与标签声明的 Resolver 结果，并验证关键日期窗口。
通过仅表示开发种子与当前代码契约相容，不代表答案已经人工审核或模型理解能力合格。
