# 年度新闻容量扩充与7／30／365天策略

2026-10-27。业务规模由用户补充，未在本地独立核验企业流量。
本次已经实际生成明确标识的合成数据，验证年度容量形状，不把它们当作真实新闻或人工金标。

## 业务口径与容量上界

用户描述每天约8000篇原始新闻，经高质量筛选及同事件事实处理后约500篇进入向量存储或更新。
原始正文与来源台账可以保留，向量库只保存符合准入的有效投影。
如果500包含旧事件更新、转载替代或重试，它不是500个净新增事件；
年度18.25万是按每日500净新增规划的上界，真实去重存量可能更低。
不要将18.25万称为已经独立验证的生产事件总数。

| 层 | 固定滚动年龄区间 | 按500篇／日的文档上界 | 按5切片／篇的向量数 |
| --- | --- | ---: | ---: |
| 热 | 0≤年龄<7天 | 3500 | 17500 |
| 温 | 7≤年龄<30天 | 11500 | 57500 |
| 冷 | 30≤年龄<365天 | 167500 | 837500 |
| 合计 | 保留365天 | 182500 | 912500 |
| 过期 | 年龄≥365天 | 不进入有效向量清单 | 0 |

一个月按30个24小时日、一年按365日，满365日即过期；这是本次候选策略的精确边界，
不是自然月／自然年、闰年规则。重新Embedding、迁层或写入台账不重置新闻发布日期。

一年原始接入292万篇；500/8000=6.25%只是两项业务数量的算术比，不是模型质量准确率。
当前规划采用本地BGE的1024维、FP32和每篇5切片：
纯向量3737600000字节，约3.48GiB。索引结构、主键元数据、正文、缓存、复制及迁移临时双份空间另计。
现有545篇真实实验新闻共有2577切片，样本均值约4.73切片/篇，因此取5作为容量起点；该样本不代表全年分布。每篇切片数和企业实际Embedding维度仍需按真实正文长度与平台接口复核。

## 本次实际生成的内容

生成根目录：`var/news-capacity-20261027/synthetic-annual-v1/`。

- `synthetic-intake.jsonl`：292万条合成原始接入元数据，准入标记由场景预设，不是假称质量模型判断。
- `synthetic-news.jsonl`：18.25万篇有效文档、1000条被替代旧版本、3500篇过期探针，共18.7万条版本记录。
- `synthetic-chunks.jsonl`：91.25万条有效切片成员记录，排除过期和被替代版本。
- `synthetic-vectors-hot/warm/cold.npy`：对应三层真实落盘的1024维FP32数组。
- `replacement-probes.jsonl`：1000个构造的“详细稿完整覆盖初始稿事实”的场景，保留两个版本的身份。
- `manifest.json`：参数、数量、数据哈希与合成标识。

向量是固定种子的归一化随机向量，模型身份为synthetic-random-normal-v1，
**不是BGE对这18.25万篇新闻的真实Embedding**，只用于容量、数据搬运和负载场景。
这些数据不得接入正式内容发布，不产生真实新闻相关性分数，也不替代用户的300项人工标注。
1000次替代和额外7天过期探针是独立构造的测试数量，不表示企业每天的更新或撤稿率。

## 事实详细度替代与索引更新

现有真实链路仍为：
NewsSemanticModel.EXTRACT抽取逐字证据与事实 →
COMPARE判断同事件、等价／单向覆盖／冲突 →
validate_features／fully_accounted／decide_pair做程序校验 →
保留版本化决定 →
NewsSemanticService.retire →
KnowledgeLifecycleService.retire_duplicate验证替代稿当前索引 →
台账退役旧稿并异步删除旧向量、读回验证。

只有同事件、无冲突与未决疑点、旧事实被完整覆盖且无独立证据必须保留时才可能替代。
程序还考虑来源优先级，不按字数直接判断高质量。
短讯含独立采访、不同数值口径、新事实或更正时，不能仅因另一篇较长而删除。
新稿索引未就绪、版本变化或验证失败时，应保留旧投影；恢复必须使用新的投影ID。
合成替代场景是构造oracle，用于容量／版本状态检查，不证明实际模型判断了1000个真实事件。

## 生产保留策略尚需接线的边界

本次7／30／365在合成工作负载中执行，并未自动改变现有真实新闻实验或正式服务。
现有生产生命周期配置已支持热温阈值和冷层迁移，候选阈值应为：
`hot_max_age_seconds=604800`、`cold_min_age_seconds=2592000`。
当前原生Schema没有365日vector TTL字段；不能向旧YAML强塞不识别的字段并宣称生效。

上线前另建版本完成：
1. 增加可选向量保留期配置，默认不影响既有数据；
2. 查询门禁立即排除到期投影；
3. 扫描器生成幂等的“向量过期”任务，区别于新闻撤稿，不删除正文事实源；
4. 分批物理删除并contains读回确认，失败保持cleanup_dirty重试；
5. 处理在途Embedding、迁层／回热与过期竞态，禁止过期数据因重试重新出现；
6. 保留版本、来源与审计，根据企业正文保留政策另行归档。

本次未把已有新闻retract接口当作TTL接口，未运行正式库删除作业。
过期探针验证的是“未进入有效成员”，不是已经验收生产平台的异步TTL回收。

## 执行入口与跨电脑复现

从仓库根目录，用具备NumPy的Python3.11环境执行；不需要GPU或企业API：

```bash
# 只看规划
python -B agent/tools/prepare_annual_news_capacity.py --plan-only

# 生成全量合成接入、文档、切片和向量；默认约5～6GB磁盘，预留更多空间
python -B agent/tools/prepare_annual_news_capacity.py --emit-raw --emit-vectors \
  --summary output/annual-capacity-20261027/local-build/summary.json

# 全量读回校验
python -B agent/tools/verify_annual_news_capacity.py \
  --output output/annual-capacity-20261027/local-build/validation.json
```

默认配置：`deploy/annual-news-capacity.profile.json`。
可指定--profile、--output-dir、--summary；验证器支持--dataset、--output。
已有目录／报告不覆盖；重跑选择新目录及新summary路径。默认时间固定，不随执行当天漂移。

批量大文件已在.gitignore排除，Git同步代码、配置、摘要、验证结果；
另一台电脑可以按相同种子重新生成，无需上传多GB数组到GitHub。
`output/annual-capacity-20261027/summary.json`保存实际构建摘要，
`validation.json`保存全量验证；生成完成后才有“已扩充”的结论。

## 完整调用链与验收

## 简历与评测如何更新

可表述为：
“面向日均约8000篇原始新闻、约500篇高质量报道入库及事件更新的业务场景，
设计7／30／365天分层保留策略；按18.25万篇年度文档上界、约91.25万条切片向量
构建合成容量回放，覆盖详细版本替代与过期场景。”

其中业务日流量来自用户说明，18.25万是规划上界，合成回放是本次实际产物；
这三类来源不能合并称为生产实测。正式项目经历还应由本人按实际情况确认。

原545篇、30查询、300人工标签仍用于小规模真实新闻相关性实验；
原63.1ms只适用于该小规模本地检索，**不能移植为18万篇年度索引或腾讯生产P95**。
下一步应在目标ANN平台导入相应规模、固定并发和查询负载，测实际检索与维护成本；
相关性质量则需要更多真实新闻和独立人工测试，不能靠复制或随机向量抬高nDCG。
