# 新闻推送运营策略目录

版本：研究目录 v1；日期：2026-10-04；状态：待运营团队校准的策略种子，不是已批准的生产策略。

## 1. 策略的本质

新闻推送消耗用户的注意力，并影响媒体可信度。完整策略必须回答：是否值得打扰、对谁有价值、何时还有价值、是否有必要再次通知、文案能否独立准确表达事实、如何观察收益与负面影响。

Reuters Institute 的 2025 年通知研究强调相关性、用户控制和避免过量/耸动通知；其不同媒体的发送量只是案例，不能换成 NewsAgent 的统一频控标准。[研究原文，2025-06-17](https://reutersinstitute.politics.ox.ac.uk/digital-news-report/2025/walking-notification-tightrope-how-engage-audiences-while-avoiding)

短通知可能是用户看到的全部信息，标题自身必须准确并保留必要归因和背景，不能指望落地文章补救误导。[AP，2018-06-29](https://www.ap.org/the-definitive-source/behind-the-news/the-challenge-of-brevity-in-the-digital-age/)

据此，下面将场景策略与横向控制都纳入运营策略目录。频控、静默时段、样本量、有效阅读阈值和过期时长均待运营确认、版本化，不填入未经本项目验证的“行业默认值”。

## 2. 所有策略的共同前置条件

- 新闻身份与事件身份明确；正文/证据版本与可引用范围可追溯。
- 已确认事实与争议信息分开；传闻、待核验材料不因热度高而获得投递资格。
- 人群只能来自已批准的地域、兴趣、订阅和分群条件；用户明细留在企业服务。
- 权限、通知偏好、排除条件、渠道、预算与有效期均有可信来源；缺失时默认不投递。
- 候选仅进入审核；批准绑定具体修订版及内容哈希，发送前再次校验。
- 更正、撤回、权限撤销、证据过期优先于普通增长目标。

AP 要求对可争议信息归因、核验互联网材料并明确更正错误。这里将编辑原则映射为证据与状态门禁，而不把一篇外部报道自动当作完整核验。[AP 编辑原则](https://www.ap.org/about/news-values-and-principles/telling-the-story/)

## 3. 十二类策略

| ID / 策略族 | 新闻场景与条件 | 运营动作 | 阻断或反例 | 审批时需要留下的证据 |
|---|---|---|---|---|
| OPS-01 新闻价值与准确性 | 对公众或明确受众有实质影响，有可信新信息 | 确认推送价值与风险；不满足条件则不推/待核验 | 热度来自传闻、旧闻翻炒、表述超出证据 | 公共影响、来源、已确认事实、限制与不确定性 |
| OPS-02 重大突发 | 事实已确认，延迟会降低信息价值或公众知情价值 | 提出立即审核；只有广泛影响才申请广域人群 | 未确认伤亡数字、与多数受众无关、仅因排行第一 | 为什么必须此时打扰、影响范围、时间线与负责人 |
| OPS-03 地域/兴趣相关性 | 地方公共服务或专业议题与已批准人群匹配 | 定向触达，必要时改用站内提示 | 将地方事件推向全站、从一次点击推断长期兴趣 | 地域/兴趣条件、排除条件、匹配依据与人群版本 |
| OPS-04 明确订阅 | 用户已选择事件、主题或类别且未撤销 | 向相应订阅范围推荐更新 | 未订阅、退订后仍触达、兴趣分群冒充授权 | 订阅类别、偏好版本、撤销检查结果 |
| OPS-05 事件增量与去重 | 相对上次通知出现已确认的关键新增事实 | 说明增量；合并重复，重要更新才再次申请 | 同事件换标题/换news_id重复；正文新版本但无重要增量 | event_id、上次版本、新事实差异、去重命中与例外理由 |
| OPS-06 时机与有效期 | 信息在指定地区/时区仍有行动或阅读价值 | 选择发送窗口；延期后重验，过期结束 | 交通管制已结束、比赛已结束仍发赛前预告 | send_after、expire_at、新闻/证据时效、延期条件 |
| OPS-07 频控与疲劳 | 企业服务可核验用户/人群、主题、事件、渠道预算 | 抑制、合并为摘要、延后；例外须另行审批 | 只有plan.frequency_limit没有实际配额；不同事件绕过总预算 | 计数窗口、单位、冷却期、预算快照/预留与例外批准 |
| OPS-08 准确文案 | 事实、主体、时间、归因与落地内容一致 | 改标题/摘要，保留必要背景；不确定性明确表达 | “史上最”“一定”等无证据断言、把预测写成事实 | 修改前后差异、支撑片段、标题/正文一致性检查 |
| OPS-09 渠道与通知偏好 | 渠道已授权且适合紧急程度、内容和隐私要求 | 普通通知/站内/摘要等选已批准渠道，尊重用户设置 | 用高优先级绕过静默或权限；锁屏展示敏感信息 | 渠道类别、偏好快照、权限、锁屏展示与设备限制 |
| OPS-10 日报/专题摘要 | 多条非紧急新闻可在固定窗口形成有价值组合 | 按主题去重、合并摘要，减少逐条打扰 | 无新信息或整理价值地重复当天已推内容，或将重大突发一直压到日报 | 组合逻辑、条目版本、回顾/重述理由、摘要窗口 |
| OPS-11 更正与撤回 | 已推荐/已发送内容出现确认错误、撤回或重要修正 | 阻断未发任务，关联更正；已发由平台能力决定补发/撤回 | 将已发通知标成“撤回成功”而无回执；以新标题遮掩错误 | 原plan/delivery引用、错误点、修正版本、平台回执 |
| OPS-12 效果验证与策略评估 | 有可信聚合结果和完整观察窗，或明确仅有审批结果 | 看有效阅读、回访、负反馈与质量，提出受控候选 | CTR增加就自动扩量；把模拟结果、无反馈、未执行当真实有效 | 分母、观察窗、样本/缺失量、选择方式、对照与证据局限 |

Guardian 的真实推送流程由编辑选择事件、地域、落地文章和文案，再确认发送，支持将这些维度作为一个完整审批对象。[Guardian 工程实践，2022-12-15](https://theguardian.engineering/blog/info-2022-dec-15-our-journey-towards-the-fastest-breaking-news-service)

AP 的内容接口区分稳定内容标识、修订版本与重复交付；在 NewsAgent 中还需区分“内容变了”和“值得再打扰”，不能把版本增加当成重推许可。[AP 修订与去重契约](https://api.ap.org/media/v/docs/Managing_Revisions_and_Duplicates.htm)

## 4. 新闻背景下的具体决策示例

以下均为合成情景，没有引用或编造真实新闻和投递效果。

| 情景 | 建议 | 可沉淀的经验 | 不能推广的结论 |
|---|---|---|---|
| 某市已确认的临时公共交通调整，仍在有效期内 | 申请受影响地域的公共服务定向通知；区域/时间不清楚先延后 | 地方服务信息需绑定影响范围和结束时间 | “公共服务消息都应该全站推送” |
| 同一体育赛事已通知赛果，新稿只改写标题 | 不再次通知，候选进入去重案例 | 事件级增量优先于文章数量 | “体育新闻价值低” |
| 社交平台传闻引发高热度，尚无可核验事实 | 暂缓，等待证据；不是改成吸引人的标题 | 证据不足阻断；记录待核验原因和重评条件 | “运营驳回说明分析内容全错” |
| 用户明确订阅的主题出现深度解释稿，非紧急 | 推荐定向/摘要，选择已批准的阅读窗口 | 阅读价值与突发时效是不同条件 | “解释稿CTR较高，所以应该扩大所有人群” |
| 已发消息确认数字有误 | 关联原消息，审核更正，核对平台可撤回能力 | 更正是独立优先路径，需保留原错误与修改血缘 | “删除文章就等于撤回了锁屏通知” |

## 5. 如何评估

审批一致性与投递效果分别报告。采纳率反映建议是否符合运营判断，不能当CTR或事实准确率；事实正确也可能因频控而不推。

| 维度 | 示例指标与必要定义 |
|---|---|
| 编辑质量 | 证据充分率、文案事实错误、更正/撤回数、必要归因完整度 |
| 决策适配 | 按理由统计采纳/驳回/延后/修正，分场景与团队；分母为可审核建议 |
| 触达质量 | 受理、送达、打开分别统计；每个比率必须绑定平台定义的分母 |
| 内容价值 | 有效阅读、回访等聚合指标，保留定义版本和完整观察窗口 |
| 打扰与信任 | 投诉、退订、关闭通知、重复打扰、偏好违背；按渠道与场景观察 |
| 数据质量 | 未执行、未知投递、迟到结果、观测缺失、样本不足各自列出 |

原始实验表明通知可能增加使用或新闻知识，但效果取决于情境；因此不把打开率作为唯一目标，也不从历史国外实验外推本地增益。[UT Austin 原始研究，2016-10-27](https://mediaengagement.org/research/mobile-news-notifications/)

无对照的观察只能写“相关/观察结果”；只有获准实验、可信分流与完整统计合同才能评估因果。实体事件应按event_id/时间做拆分，避免同一事件改稿同时进入训练参考与评测集。频控和退订约束不能用实验覆盖。

## 6. 来源与适用范围

检索日期为2026-10-04。上述新闻编辑原则、用户研究和系统机制是设计依据；策略族及优先级是对 NewsAgent 的工程综合建议。它们不是中国用户频控基线，也不是生产授权。

通知应简明、及时、避免重复并尊重用户许可与敏感信息展示；实际设备表现由企业平台与用户系统设置共同决定。[Apple Notifications](https://developer.apple.com/design/human-interface-guidelines/notifications)

Android 的通知渠道支持用户控制类别的重要性；应用不应借改变渠道绕过用户选择。[Android 通知渠道官方文档](https://developer.android.com/develop/ui/compose/notifications/channels)
