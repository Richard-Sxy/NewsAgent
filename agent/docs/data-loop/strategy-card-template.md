# 运营策略卡模板

日期：2026-10-04；契约建议：operations-strategy-card-v1；状态：设计模板，暂无运行时加载器。

复制下面的模板建立一条策略。未填字段、未经审批或缺少证据的卡保持 `draft`，不进入可选生产策略集。Markdown用于评审和导出；未来注册表应保存规范化结构、内容哈希和审批账本，不能把任意Markdown当作可执行脚本。

## 模板

```yaml
---
schema_version: operations-strategy-card-v1
strategy_id: <稳定ID，例如 ops-local-public-service>
strategy_version: <不可变修订版，例如 1.0.0>
status: draft # draft / in_review / approved / active / retired / revoked
title: <策略名称>
strategy_family: <OPS-01到OPS-12的一项或组合>
scope:
  tenant_id: <租户ID>
  operations_team_id: <运营团队ID>
  allowed_topics: []
  allowed_region_codes: []
  allowed_channels: []
objective: <公共服务/及时知情/订阅阅读/纠错等>
owner_id: <业务负责人>
source_decision_ids: []
source_case_ids: []
counterexample_case_ids: []
source_outcome_refs: []
evidence_level: seed # seed / reviewed_cases / observational / controlled_experiment
proposed_by: <提出者>
approved_by: null
approved_at: null
valid_from: null
review_due_at: null
valid_until: null
supersedes_strategy_version: null
strategy_set_version: null
content_sha256: null # 注册时由Python对规范化内容计算，不能自填证明审批
---
```

### 1. 适用场景与业务目标

描述新闻背景、受众价值和为什么需要推送。区分通用编辑约束与某地区/主题的经验规则。

### 2. 正向匹配条件

写成服务端可核验的条件：事件类型、地域、证据状态、主题、明确订阅、内容有效期、关键增量、可用渠道。每个条件注明数据来源和缺失时处理方式。禁止模型自造可信标签、权限或配额。

### 3. 排除条件与反例

例如未经确认的事实、地域不明、无新增事实、通知权限撤销、预算不足、正文更正/撤回、已过有效期。列出足以推翻策略的反例，不只保留成功案例。

### 4. 推荐动作

明确候选动作、目标人群结构、排除范围、渠道、标题与摘要要求、时间窗口。只指向批准的人群维度；企业人群平台返回版本化快照和聚合人数，不返回原始用户明细。

### 5. 参数与执行护栏

| 参数 | 值 | 单位/时间窗 | 来源版本 | 批准人/时间 | 缺失时行为 |
|---|---|---|---|---|---|
| 发送窗口与时区 | 待定 | 明确时区 | 待定 | 待定 | 不生成可投递计划 |
| 有效期 | 待定 | 时间戳或时长 | 待定 | 待定 | 不投递 |
| 频控与冷却期 | 待定 | 用户/主题/事件/渠道及滚动窗 | 待定 | 待定 | 不投递，不假设剩余配额 |
| 例外范围 | 待定 | 指定场景/人群/渠道 | 待定 | 待定 | 不启用例外 |
| 评测样本门槛/容忍退化 | 待定 | 场景与数据集分层 | 待定 | 待定 | 不晋升 |

### 6. 人工审批

区分单条建议、标签、策略和配置发布审批。记录职责分离、审批对象修订版/哈希、推广范围与到期时间。普通建议采纳不能自动给策略卡填入 `approved_by`。

### 7. 证据与评测

列出来源案例、当时新闻/正文/证据/建议快照、运营原始理由和经二审的标签。真实效果需带数据定义、分母、窗口、缺失率和平台引用；模拟/shadow结果只说明链路行为。

记录Golden/Fresh/High-risk数据集版本、线上与上一实验基准、受控策略候选版本、评测报告URI和哈希。没有真实结果可以提出编辑经验候选，但不能宣称带来效果提升。

### 8. 冲突解决、失效与回滚

推荐约束顺序：身份/权限与编辑事实门禁 → 更正/撤回处理 → 用户授权和排除 → 频控/去重/有效期 → 场景与渠道 → 表达。更正通道也必须遵守授权，不把更正理由当权限绕过。

同级策略冲突要由确定性优先级或转人工解决；不能交给模型任意覆盖。写清失效条件、撤销负责人、受影响未发计划、策略集回滚目标和重新审批要求。

## 版本生命周期

```text
draft → in_review → approved → 人工激活到策略集 → active
             ↓ 修改后另建版本                    ↓
           draft                         retired / revoked
```

`approved`表示版本经过审核，`active`还表示它进入指定作用域的有效策略集。内容、适用范围、参数或核心证据改变后，必须新建版本和哈希，不保留旧审批覆盖新内容。快照固定版本，但撤回/权限撤销等即时阻断条件仍在使用前检查。

## 最小案例：本地公共服务策略种子

策略族：OPS-03 + OPS-06；状态：draft；证据等级：seed。

条件：已确认的公共服务信息；影响地域和结束时间明确；可由企业平台解析已批准地域人群。

动作：提出定向候选，保留生效/结束时间和必要来源归因，交运营审批。

反例：预告尚未确认或缺少明确安排、受影响区域未确定、措施已经结束、同事件无重要增量、人群权限不可核验。

待补：运营负责人、具体时间与频控政策、真实审核案例、独立标签复核、聚合效果、评测报告。此种子不会自动进入下一次运行。
